# 站内信通知节点

站内信通知节点用于在工作流执行过程中向指定人员发送站内消息。消息会直接送达接收人的站内消息中心，无需依赖邮件服务配置。

## 适用场景

- 任务指派后通知负责人处理
- 记录状态变更时通知关注人
- 流程节点到达时提醒处理人
- 数据异常时向空间全体成员广播提醒

## 与发送邮件节点的区别

| 对比项 | 站内信通知节点 | 发送邮件节点 |
| --- | --- | --- |
| 送达位置 | 系统内消息中心（导航栏消息铃铛） | 接收人邮箱 |
| 前置条件 | 无需额外配置 | 需管理员配置 SMTP 邮件服务 |
| 接收人 | 系统内用户（按用户身份定向） | 邮箱地址，可发给外部人员 |
| 消息内容 | 纯文本 | 支持模板与 HTML |
| 外部人员 | 不支持 | 支持 |

如果既需要站内提醒又需要邮件通知，可以在工作流中同时添加这两个节点。

### 接收人来源

接收人来源支持同时勾选多项，各来源解析出的接收人会自动合并去重，同一个人只会收到一条消息。

| 来源 | 说明 | 额外配置 |
| --- | --- | --- |
| 指定成员 | 从当前空间成员中选择固定人员 | 需选择至少一名成员 |
| 成员字段 | 从触发记录的成员类字段动态解析接收人 | 需选择至少一个成员、协作人或创建人类型字段 |
| 流程触发人 | 动态取触发本次工作流的用户 | 无需额外配置 |
| 记录创建人 | 动态取触发记录的创建人 | 无需额外配置 |
| 空间全部成员 | 向当前空间的全部成员批量下发 | 无需额外配置 |

### 指定成员

勾选「指定成员」后需要选择具体人员，可多选。候选项限定为当前空间的成员，支持搜索。

### 成员字段

勾选「成员字段」后需要选择字段，可多选。仅支持成员、协作人、创建人类型的字段；运行时会读取触发记录中这些字段的值并解析为接收人。

### 消息标题

必填，支持静态文本和变量引用。最长 500 个字符，超出部分会自动截断。

### 消息正文

支持静态文本和变量引用，按纯文本处理。

## 可用变量

- `{{record.<字段ID>}}`：触发记录字段
- `{{trigger.record.<字段ID>}}`：触发记录字段（等价写法）
- `{{node_outputs.<节点ID>.result}}`：前置节点的输出结果
- `{{loop.current_data.<字段ID>}}`：循环节点当前迭代的数据

在配置面板中，标题和正文输入框下方会列出当前可用变量，点击即可复制。处于循环体内时，还可以通过变量插入器插入循环变量。

## 使用示例

### 示例一：任务指派后通知负责人

表格中含「负责人」（成员字段）和「任务名称」字段，新任务创建时通知负责人。

| 配置项 | 值 |
| --- | --- |
| 接收人来源 | 成员字段 |
| 成员字段 | 负责人 |
| 消息标题 | 新任务：{{trigger.record.<任务名称字段ID>}} |
| 消息正文 | 你有一个新的待处理任务「{{trigger.record.<任务名称字段ID>}}」，请及时处理。 |

### 示例二：记录变更后通知创建人与触发人

记录状态被修改时，同时通知记录的创建人和本次修改的操作人。

| 配置项 | 值 |
| --- | --- |
| 接收人来源 | 记录创建人 + 流程触发人 |
| 消息标题 | 记录状态已更新 |
| 消息正文 | 你关注的记录状态已变更为「已完成」。 |

若创建人与触发人是同一个人，合并去重后只会收到一条消息。

### 示例三：向空间全体成员广播

| 配置项 | 值 |
| --- | --- |
| 接收人来源 | 空间全部成员 |
| 消息标题 | 数据巡检告警 |
| 消息正文 | 检测到 3 条异常记录，请及时处理。 |

## 注意事项

- 站内信只发送给系统内已存在的用户。解析不到任何有效接收人时，该节点会跳过并记录告警，**不会中断后续流程**。
- 单个节点最多向 200 人发送，超出部分会被截断并在日志中告警。
- 消息标题为必填项，未填写时工作流无法保存；这是为了避免流程执行到该节点时才报错中断。
- 消息正文按纯文本渲染，写入前会做 HTML 转义，不支持富文本样式与超链接。
- 接收人可在导航栏消息铃铛看到未读红点，进入消息中心后该消息的来源标记为「工作流」。
- 循环体内也可以使用站内信通知节点，但「成员字段」来源读取的是触发记录，而非当前迭代的循环项；如需按循环项取值，请在正文中配合循环变量使用。
