# 审批流

审批流是一套完整的流程编排与执行引擎：管理员通过可视化画布设计流程节点与流转规则，终端用户从表格记录发起审批，审批人按流程顺序处理任务。审批流与数据表深度绑定——审批表单从表结构自动生成，每条审批实例关联一条表格记录。

> 审批流为**专业版**功能。典型场景：请假申请、费用报销、合同审批、入职审批、采购申请等。

## 核心概念速查

**审批流状态**：草稿（可自由编辑）→ 已发布（可发起，配置变更受限）→ 已暂停（不可发起新实例，可编辑）→ 已归档。

**节点类型**（6 种）：

| 节点 | 说明 | 数量要求 |
|---|---|---|
| 开始节点 | 定义发起人需填写的表单字段 | 有且仅有 1 个 |
| 审批节点 | 创建待办任务，审批人通过 / 驳回 / 转交 | 可多个 |
| 抄送节点 | 通知相关人员，无操作权限 | 可多个 |
| 条件分支 | 根据记录字段值选择后续路径 | 可多个 |
| 自动填写 | 自动回写表格字段 | 可多个 |
| 结束节点 | 流程终点 | 有且仅有 1 个 |

**审批模式**（3 种）：

| 模式 | 执行逻辑 |
|---|---|
| 或签 | 任一审批人通过即关闭其他待办，继续流转 |
| 会签 | 所有审批人都通过后才继续 |
| 串行 | 按顺序逐个创建任务，前一人通过后为下一人创建 |

**审批人来源**（5 种）：固定人员、单成员字段（如"直属主管"）、多成员字段、Base 角色、记录创建者。

## 快速开始

1. **前置准备**：准备包含业务字段的数据表（成员字段可用于动态指定审批人），确保审批人已加入 Base
2. **创建**：Base 侧边栏 → 审批流管理 → 新建审批流 → 选择所属表格、填写名称
3. **设计节点**：从左侧面板添加审批 / 抄送 / 条件 / 自动填写节点，右侧面板配置审批人来源与模式；拖拽连线设置流转路径
4. **配置表单**：点击开始节点 → 表单字段标签 → 勾选发起时显示的字段，设置必填、标题覆盖、占位符、显示模式
5. **发布**：点击发布按钮，系统校验完整性（开始/结束节点、审批人配置、出边）后生成版本快照

## 流程设计详解

**画布操作**：添加 / 选中 / 移动 / 连接节点（从节点右侧圆点拖拽）、断开连线（Delete）、缩放、小地图导航。

**节点配置要点**：

- **审批节点**：审批人来源 + 审批模式 + 超时时间与超时动作 + 字段权限（可写 / 只读 / 隐藏）
- **条件分支**：为每个分支设置条件（字段 + 操作符 + 值，支持 AND/OR），建议始终配置默认分支
- **自动填写**：配置目标字段与写入值的映射（如审批通过后自动将"合同状态"设为"已生效"）
- **节点连线**：每个节点必须至少有一条出边

**发起时字段显示模式**：normal（可编辑）/ read-only（只读）/ hidden（隐藏）。

## 版本管理与发布

每次发布生成**不可变版本快照**。核心机制：**审批实例启动时冻结使用的版本号**，后续修改（暂停 → 修改 → 重新发布）生成新版本，但不影响已运行实例——运行中的实例按启动时规则完成，新规则只对新发起的审批生效。

| 配置项 | 草稿 | 已发布 | 已暂停 |
|---|---|---|---|
| 名称 / 描述 | 可改 | 可改 | 可改 |
| 关联表格 | 可改 | 不可改 | 不可改 |
| 节点 / 表单配置 | 可改 | 不可改 | 可改 |

设计页面的"版本历史"可查看所有版本及其快照详情，并支持版本差异对比。

## 发起审批

三个入口：

1. **表格操作**：选中记录 → 更多操作 → 发起审批 → 选择已发布审批流
2. **发起页面**：Base 侧边栏 → 发起流程，按关联表格分组展示可发起的审批流
3. **自定义应用**：管理员可将"发起流程"页面集成到应用中（支持跨 Base 聚合）

发起表单会自动填充记录数据（只读），必填字段校验后提交；提交前可实时预览流程路径。

## 审批处理

**入口**：侧边栏 → 审批事务 → 我的待办。

- **通过**：查看流程图（高亮当前节点）与表单数据 → 填写审批意见（可选）→ 确认通过。或签模式下任一人通过自动关闭同节点其他待办
- **驳回**：**必须填写驳回意见**；驳回终止整个实例，同节点所有待办自动关闭，系统自动创建**返回任务**发给发起人
- **转交**：选择新审批人，流程进度不变
- **重新提交**：发起人在"我发起的"中处理返回任务，修改可编辑字段后重新提交，流程从被驳回节点的上一个已完成节点重新开始（已通过节点不重复执行）
- **作废**：驳回后发起人可选择作废，实例状态变为"已取消"
- **审批时编辑字段**：节点配置了可写字段时，审批人可直接修改字段值并同步写入数据库

## 审批事务与实例详情

审批事务包含 4 个视图：**我的待办 / 我的已办 / 抄送我的 / 我发起的**（抄送事项仅可查看）。

实例详情弹窗（支持全屏）提供：

- **流程图**：节点实时状态标注（当前节点橙色、已完成绿色、已驳回红色、已退回橙色、已转办蓝色、自动关闭灰色、未到达虚线）
- **节点轮次时间轴**：驳回重提产生的多轮执行记录（到达时间、处理时间、审批人、意见）
- **表单数据**：按字段类型智能渲染；审批中编辑过的字段显示修改后的值
- **评论与流转历史**：审批意见时间线、手动评论、完整事件记录（启动 / 通过 / 驳回 / 转交 / 返回 / 重提 / 作废 / 完成）

## 在自定义应用中集成

- **流程发起页面**：绑定一个或多个已发布审批流（支持跨 Base），以卡片列表聚合展示
- **审批事务页面**：包含与 Base 版一致的 4 个子 Tab，仅展示管理员绑定的流程数据，按用户权限隔离

## 通知与提醒

| 触发事件 | 通知对象 |
|---|---|
| 新待办创建 | 审批人 |
| 审批通过 / 驳回 / 流程完成 | 发起人 |
| 任务转交 | 新审批人 |
| 抄送 | 抄送人 |

启用实时协作（`REALTIME_ENABLED=true`）时，新待办通过 SocketIO 实时推送，无需刷新页面。

## 权限说明

| 角色 | 创建/设计审批流 | 发起审批 | 审批处理 |
|---|---|---|---|
| Owner / Editor | ✅ | ✅ | ✅（是审批人时） |
| Viewer | ❌ | ✅（对关联表格有权限时） | ✅（是审批人时） |

## 常见问题

- **发布按钮灰色**：审批流不完整（缺开始/结束节点、审批节点未配置审批人）或无 EDITOR 以上权限
- **修改审批流影响运行中实例吗**：不影响，实例按启动时冻结的版本执行
- **条件都不满足时**：走默认分支；未配置默认分支流程会停止并记录警告，**建议始终配置默认分支**
- **待办列表为空**：确认审批流已发布、审批人来源解析结果包含当前用户
- **驳回后重新提交**：已通过节点不重复执行，被驳回节点及其之后重新创建任务
