# 场景实践：研发缺陷管理

## 适用场景说明

本方案适用于软件开发团队对缺陷（Bug）进行记录、分配、修复和验证的完整流程管理。通过 SmartTable，研发团队可以统一缺陷入口、跟踪修复进度、统计缺陷分布，并与测试用例、版本计划等数据关联。

典型适用对象包括：

- 测试工程师提交和跟踪缺陷。
- 开发负责人分配修复任务。
- 项目经理统计版本质量指标。

## 推荐的表结构设计

建议创建一张名为「缺陷管理」的数据表，核心字段如下：

| 字段名称 | 字段类型 | 说明 |
| --- | --- | --- |
| 缺陷标题 | 单行文本 | 缺陷的简短描述，作为记录主标题。 |
| 缺陷编号 | 自动编号 | 自动生成唯一编号，便于追踪和引用。 |
| 所属项目 | 单选 | 缺陷所在项目或产品模块。 |
| 影响版本 | 单行文本 | 发现缺陷的版本号，如「v1.5.2」。 |
| 严重级别 | 单选 | 可选值：致命、严重、一般、轻微、建议。 |
| 优先级 | 单选 | 可选值：紧急、高、中、低。 |
| 缺陷状态 | 单选 | 可选值：新建、已确认、处理中、待验证、已关闭、已拒绝。 |
| 提交人 | 成员 | 提交缺陷的测试人员。 |
| 负责人 | 成员 | 负责修复的开发人员。 |
| 验证人 | 成员 | 负责验证修复结果的测试人员。 |
| 提交时间 | 日期时间 | 缺陷提交时间。 |
| 期望修复时间 | 日期 | 计划完成修复的日期。 |
| 实际修复时间 | 日期 | 开发完成修复的实际日期。 |
| 复现步骤 | 多行文本 | 详细描述缺陷复现步骤。 |
| 截图/日志 | 附件 | 上传缺陷截图、日志文件或录屏。 |
| 关联需求 | 关联字段 | 关联到「需求管理」表，建立缺陷与需求的联系。 |

## 推荐的视图配置

### 看板视图（按缺陷状态分组）

- 分组字段：缺陷状态
- 排序规则：严重级别降序、优先级降序
- 用途：直观查看缺陷从「新建」到「已关闭」的流转情况。

### 表格视图（按负责人筛选）

- 为每位开发人员创建筛选视图，只显示分配给该成员的缺陷。
- 便于开发日常 focus 在自己负责的缺陷上。

### 分组视图（按严重级别分组）

- 分组字段：严重级别
- 用途：快速识别高优先级缺陷，优先处理致命和严重问题。

### 日历视图

- 日期字段：期望修复时间
- 用途：查看每日到期需要修复的缺陷，合理安排开发计划。

## 可选的工作流自动化建议

| 自动化场景 | 触发器 | 节点配置 |
| --- | --- | --- |
| 新缺陷通知 | 记录创建触发 | 调用 Webhook 节点通知开发负责人和项目群。 |
| 状态变更同步 | 记录更新触发（缺陷状态变化） | 更新记录节点记录状态变更时间，当状态为「待验证」时通知验证人。 |
| 逾期缺陷升级 | 指定时间触发（每日运行） | 条件节点判断「期望修复时间小于今天且状态未关闭」，更新记录节点将优先级提升为「紧急」。 |
| 缺陷关闭归档 | 记录更新触发（状态变更为已关闭） | 更新记录节点记录实际关闭时间，并发送关闭通知给提交人。 |

## 简要的操作步骤

1. 创建「缺陷管理」数据表，添加上述字段并配置单选选项。
2. 设置「缺陷编号」字段为自动编号，保持编号连续性。
3. 创建看板视图、分组视图和按负责人筛选的表格视图。
4. 测试人员提交缺陷时，填写复现步骤并上传截图或日志。
5. 开发负责人根据严重级别和优先级分配修复人。
6. 开发人员修复后更新状态为「待验证」，验证人确认后关闭缺陷。
7. 配置工作流自动化，实现新缺陷通知和逾期升级提醒。
